# 这套新增的东西好在哪儿（大白话版）

> **给谁看**：Owner，以及要接手这件事的人。不讲 orchestra 原有的 A2A / Lane / `team.json` 是怎么运作的；只讲**新增的部分**与**整体逻辑**。
> **一句话**：它给多 agent 加了一层「**账房 + 门房**」——不改变谁做什么（那是编排），只改变"**什么算做完了、以及凭什么这么说**"。

---

## 一、它治的不是"某个 agent 不够聪明"，而是四种结构性病

多 agent 跑真活时，最贵的返工从来不是"这个 agent 笨"，而是下面四种，而且它们**和模型强弱无关**：

1. **谁都会说"我做完了"。** 角色分离解决了"自己给自己打分"的偏向，但**没解决证据来历**：一个独立的审查者照样可以在错的目录、错的环境变量下跑一遍测试，然后报绿。
2. **结论和版本脱钩。** 审查通过的那一版，往往不是最后合进去的那一版——在人类团队里靠流程和记忆兜着，在 agent 群里**没有一个人记得住"那份 PASS 是对哪一版的"**。
3. **并发没有事务。** "我先检查了分支是最新的"和"我真的合并"之间永远有一个时间差。这不是 agent 的错，是**缺一个比较并交换（CAS）**。
4. **状态住在对话里。** 会话一断，就只能靠重读长对话重建。你们那轮 29 小时的实测正是这个形状：平均每次调用 35 万上下文、99% 的花费是**反复重读**。多 agent 的成本结构里，**最贵的不是思考，是"重新理解"**。

## 二、新增的九件事：每件治哪个病、买到什么、买不到什么

| # | 新增的东西 | 治哪种病 | 它买到的 | 它**买不到**的 |
|---|---|---|---|---|
| 1 | **宿主采集证据**：验收由插件进程自己跑，采集命令/目录/环境/退出码/输出与产物 hash | 病一（自述不是证据） | "谁采集的"取代"谁说的" | 不保证被测程序内部没做别的事 |
| 2 | **候选身份**：候选 = 一个 commit + 冻结的验收清单 + 冻结的决策集；任一变则旧审查旧证据自动失效 | 病二（结论脱钩） | 相当于给多 agent 装上"检查绑定到 commit" | 不保证代码是对的 |
| 3 | **合并门 + CAS** | 病三（并发无事务） | 真并发下也能机械拒绝 | 不提供"冻结主干"这种全局锁（也不需要） |
| 4 | **写面租约 + 收工对账**：开工申报写面、重叠排队、收工拿申报范围对实际改动点名 | 病三的邻居（互相踩） | **准入可控 + 事后可见** | **拦不住任意文件写入**（DSH 没有 hook 位）——所以它是"被发现"，不是"不发生" |
| 5 | **节点记录 + 交接胶囊**：机器能推的字段插件自动生成，人只填机器推不出来的（下一步/已知失败/不可重复动作） | 病四（状态住在对话里） | 新会话只读"胶囊 + 记录 + git"就能续做 | 不保证胶囊的内容质量（那是角色的责任） |
| 6 | **运行期不提权 + 带默认值的请示** | 无人值守挂死 | 权限在派发时钉死；问题必须自带"不回答我就按 X 做"，然后**继续干**——**根本没有"等待"这个动作** | 不保证模型不会**尝试**提权（只是不会卡住） |
| 7 | **运行前提声明与实际一致**（树/环境/模式/外呼有无） | 假绿（最贵的一类） | "声明要跑真链、实际一步外呼都没有"这种假绿会被判**不合格** | 不能强制禁止外联（没有网络平面），只能让它**看得见** |
| 8 | **设计门由独立会话作出**（+ 记录双方用的模型） | 设计级盲区 | 堵掉"设计根本没被独立审过"这种洞（上轮 E2E 里那条车道的 reviewer 从头到尾没被物化） | **换会话 ≠ 换模型**：买到的是"没有作者的上下文污染"，买不到"不同的先验知识" |
| 9 | **两条元规则**：一条机制必须指得出一个已付过成本的故障；实现必须保持是大头，计划+验证长期超标就**回头删机制** | 这套东西自己长胖 | 唯一一条约束"以后不要乱加东西"的规则 | 它靠人真的去看配比、真的删 |

## 三、厚不厚？——**机器变厚，不是 agent 变厚**（口径已修正）

- **编排环**（谁做什么、拆几个角色、几轮、要不要加评审）——**几乎没有变厚**，这是刻意的。
- **交付路径**——**变厚了，但厚在代码和脚本上，不在 agent 身上**：
  - **宿主侧新增**：租约与写面对账、候选身份与代数、验收执行与字段采集、基线采集与差集、树比对与 CAS、节点记录与账本、豁免集与决策队列的自清理。这些**全部由插件进程里的代码执行**，不需要额外的模型回合。
> **V8② 更正（`docs/ruling-d1-d5-oracle.md` §4.3 ②）**：本节原有一句"**不消耗任何模型上下文**"，那是**过强的陈述**，已删除。**正确的口径是：模型的工作确实增加了**——新增了工具调用，多轮返修要重新冻结，复核要读记录。
> **工具调用数不是全部摩擦**：它量不到"返修时重读记录""重新冻结候选"这类开销，所以**不能**把它当成全部代价，更不能据此声称"零上下文代价"。
> **怎么量才对**：宿主侧的机械量**不占模型回合**（这一半成立，但只说这一半就是上面那句过强陈述）；**agent 侧的成本要用"每节点额外工具调用 / 轮次"来量**，而不是用"多了几个概念"来量。

- **agent 侧真正新增的，只有一个节点 3 次工具调用（典型；确有真实请示时第 4 次）**：① 申报这次要动哪些文件；② 写一次"我打算怎么做 + 截止时间"（带默认值的请示）；③ 交报告时补三个机器推不出来的字段（下一步 / 已知失败 / 不可重复的外部动作）。
  - 换句话说：**agent 的工作量基本没变，多出来的是"被记账"这件事本身。** 判断这套东西值不值，看的不是"多了几个概念"，而是"**每个节点多花的那 3 次工具调用，能不能换掉一次返修**"——换掉一次就赚。（原写"2–3 次"：与计划 §9.1 定稿的 `== 3 + decisions` 不符，随 V8 的文档更正一并改齐）
- 评估口径也应该跟着改：不看"新增了多少机制"，只看两个数——**agent 侧每节点的额外工具调用/轮次**，以及**节点记录里的 `ratio{plan, implement, verify}`**。
- 严格度全压在"交付"，没有压到"探索"。设计上刻意拒绝了三件事——开工前完备性闸、词汇闸（不许造新词）、整批拒的原子收工；它们都会压制探索或制造活锁。

## 四、摩擦在哪（不美化，但按"谁承担"分开看）

> 前三条里的绝大部分由**机器**承担；真正落在 agent 身上的是最后一条的量级。

1. **每个交付型节点多 2–4 步机械动作**（申报写面、冻结验收清单、跑宿主验收、对账）——**其中只有第 1 步由 agent 发起**，其余都是宿主代码在跑。
   对"改个错别字"这种活，确实可以走**轻量档**（裁剪设计门、架构守卫、单写者时的租约、胶囊），**但轻量档不是"免检"**：只要改动要进集成分支，**候选身份、合并门 + CAS、宿主采集读数**这三样一样不能少；而且**分级必须写在节点记录里、默认是标准档、轻量档要写明理由、轻量档的比例要进定期报告**（详见 `docs/plan-0.8.0-delivery-layer.md` §1.1）。理由很直白：**"结论被挪到新代码上"这个最贵的故障，恰恰最容易发生在没人当回事的小改动上。**
2. **晚到的答案会让候选作废**：决定在候选冻结之后才到 ⇒ 代数 +1、旧证据失效，得重跑验收与增量复审。→ 已规定"可能改变验收判据的问题必须**在冻结前**问"；且重跑主要是机器时间（见下节"候选身份"的说明）。
3. **记账与现实不一致要停机报账**。这是**故意**的：换来的是"不会被静默糊过去"。
4. **三样东西会自然长大**（豁免集、决策队列、缺陷登记）。→ 各加了自清理约束：豁免必须带理由且每次打印；可默认类必须自动结案；登记设上限、超限先清理。
5. **写面隔离不是真隔离**：两个 agent 同时改同一处，它**不能阻止**，只能**发现**。这是平台天花板。

## 五、我的判断

**净收益是正向的，但有前提。** 三个条件同时成立时收益最大：**交付型任务**（有明确的"做完"）、**多会话并发**（真的有人抢同一个写面）、**无人值守**（没人盯着点确认）。反过来，单会话探索、或者有人全程盯着看，这套东西的收益趋近于零，而成本是真的。

用你们自己的实测口径说：那轮 29 小时里协调占了 44% 的 token。如果这套东西能把"几乎每个节点至少返修一次"压下来，省的是实现+审查+合并验证那 51% 里的一大块；**如果它只是把协调成本从 44% 推到 55%，那就是亏的**。所以真正的成败不在机制本身，而在两条元规则是否被真的执行——尤其"实现必须是大头"那条：**要真的记录配比，真的在超标时删机制**。

**真正的风险不是"太厚"，而是"降级静默发生"**：设计门在这个部署里会长期是降级状态（只有一个主力模型）、外呼不可强制、写面只能对账。这些都写进了"不得声称"清单，而且对方加了一条关键要求——**降级必须可见**（进定期报告）。我把它当成这套设计的体检指标：

> **如果定期报告里看不到"降级 / 豁免 / 决策队列 / 三段配比"这四项，这套东西就已经退化成新的"文档承诺"了。**

## 六、一句话总结

它不是把多 agent 变成流水线，而是**给多 agent 配了一个账房和一个门房**：账房保证"发生过什么不可赖账"，门房保证"没满足条件的东西进不了集成分支"。它故意不碰"怎么做"，因为它知道——**探索一旦被流程掐住，这套东西就白做了**。
