## P-1（最高优先 · 弹性）：档 0 的谓词必须改掉"执行会话 = 1"

**当前写法不能保证小用法零成本**：两个**执行会话纯聊天**（不交付任何东西）**进不了档 0**（谓词限定执行会话=1），而轻量档仍有四项底座，兜不住 —— 这与需求 §2"扩展可选、既有拓扑不变"**不一致**。

**最小修改（不新增机制）**：
- 档 0 **不限制聊天会话数**；**交接 / 依赖只统计"交付型"**会话与节点；
- 保留对**全部交付动作**的硬禁（合并 / 发布 / 可复用 PASS）；
- **标准档默认只作用于"已准入的交付节点"**；P3-6 的消息指针纪律**只管交付消息**；
- **准入判定只看插件可见的交付动作、产物引用与依赖**，**不采信 driver 的"不交付"标签**（宿主外的自主写文件/合并无法强制阻止，但**不得包装成已治理交付**——见 `capability-boundaries.md` #7）。
