# ADR-0008 · 图模型：有界无环图 + 有界 Loop

- 状态：Accepted
- 日期：2026-09-15
- 来源：用户口述（"有界无边"）+ handoff §4.4，用户已确认解读

## 背景

用户在描述编排模型时说的是"有界无边图"，并明确让实现方按 DAG 的标准理解。
2026-09-12 的解读经用户在附录 A 前确认。

## 决定

1. **本体是 DAG（有向无环图）**；"有界无边"是音近误记。
2. 叠加两条工程约束才是本插件需要的图：
   - **有界**：节点集有限，且**每条执行路径的长度有限**（不允许"永远跑不完"的路径）。
   - **无环**：节点之间不得存在任意回边。
3. **Loop 是 DAG 的受控补丁，且是唯一允许的回边**：
   - 回边**带次数上限**（`maxAttempts`）；
   - 必须有**三个明确出口**：pass / retry / capExhausted，缺一不可；
   - 无出口的 Loop 视同无界。
4. 一次编排可以有**若干个 Loop**，每个 Loop 包含**若干节点**（典型 2–4 个）。
   **节点更多不等于更严谨。**
5. 结构约束（P6–P9）由 validator 机器校验，不靠纪律：
   每条路径可达 Closure、每个 Loop 有出口、Loop 之外无回边、无不可达节点。

## 后果

- **P9（无不可达节点）必须报错而非忽略**：声明了却不在任何路径上的节点是设计缺陷 ——
  它派发不到、不拥有决定、不在通往 closure 的路径上，而作者以为它在跑。
- **校验从"第一个声明的 protocol"开始生效，到此为止**：无 protocol 的拓扑是 v0.3 形态，
  catalog 早已分类为 ready-with-a-warning —— 保持可读，**绝不静默替换**。
  这条边界是既有决策，不是疏漏（曾有一版改动把 legacy 判为非法，被项目自己的测试抓了出来）。
- ADR-0006 的薄核心**不得削弱**这里的任何一条结构约束：压掉的是记账仪式，
  不是有界性与可达性。
