# ADR-0005 · 阅读深度边界

- 状态：Accepted
- 日期：2026-09-15
- 来源：用户口述（2026-09-15）

## 背景

审计把"会话间阅读"判为黄灯：`a2a_read` 只能读最近 ≤20 条、每条截断 600 字、
且只取 `user/message`（source 为 `a2a`/`user`）与 `assistant/message`，
不含工具调用、diff、token 用量（`src/a2a.ts:393-424`）。

用户回复：

> 它可以被增强，但是由于我们有一个插件叫 OBELISK，它现在是可以解析 session 记录的、
> session 的 log 的，所以这个 read 倒是也不必要做的特别的强。

## 决定

1. `a2a_read` 的定位是**有界窥视**：回答"这个会话在干什么、进行到哪了"，
   服务于**决定要不要给它发消息**，不服务于深度审计。
2. **不在本插件里重造 session log 解析**：完整 transcript / 工具调用 / diff 的深度阅读
   交给 OBELISK。两个插件职责不重叠。
3. 因此「读内容」这个管理动作的实现成本很低 —— 它是 ADR-0003 里最便宜的一项，
   不构成攻坚项。

## 后果

- 工具描述必须**诚实**说明它是窥视而非全文，否则模型会基于"我读过全文"做出错误判断。
- `limit` 与截断长度维持现状即可，不为"读得更多"扩容。
- 一个**耦合风险**记录在案：OBELISK 同样读 session log，
  所以 ADR-0002 的 P0 阻断项（自定义事件让日志整份作废）会**同时**打掉 `a2a_read`、
  GUI 打开、冷恢复和 OBELISK。P0 必须排在阅读增强之前。

## 未决
