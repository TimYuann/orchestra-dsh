### A. 仓库交付门（GitHub 级语义）

**要达成的效果**：一个"节点"产出的代码，只能在**可判定条件全部成立**时进入集成分支；任何条件失效都必须**机械拒绝**，而不是靠角色自觉。

| # | 能力 | 说明（用 GitHub 的话说） |
| --- | --- | --- |
| A1 | **候选身份绑定** | 候选 = 一个 commit（含 tree）+ 冻结的验收清单 + 冻结的决策集。三者任一变化 ⇒ 之前的审查结论与证据**自动失效**（等价于 GitHub 的 "status checks are bound to a commit SHA"） |
| A2 | **由系统执行验收** | 验收命令由 orchestra 自己跑（不是采信角色自述），并把 `命令 / cwd 与源码根 / 运行时身份 / 环境 profile / 是否允许真实外部调用 / 退出码 / 结果摘要` 一起**不可变落盘**。**从错误的 worktree 或错误的 PYTHONPATH 跑出来的结果必须判为不合格**，不得升级为通过 |
| A3 | **合并门 + CAS** | 合并前做"分支是否仍是最新"的检查；合并用**对当前集成分支 head 的 compare-and-swap**；合并后**核对结果树**是否等于预演的组合树。head 已前进 ⇒ 重新预演；不成立 ⇒ 拒绝。**不需要"冻结 main"这种全局锁** |
| A4 | **合并后失败不可回卷** | 合并后检查失败 ⇒ 记成"已合并但验证失败"的**终态**，不允许把原节点改回"再改改"；只能按授权精确 revert，或新建修复节点 |
| A5 | **worktree 隔离与单一写者** | 每个节点在自己的 worktree/分支上工作；同一写面同一时刻只有一个活跃写者；写权**在候选冻结后**才能移交。**硬约束：worktree 一律落在项目目录内**（会话在项目根启动，工作区外的写会撞权限墙、且无人值守时没人能点确认）；因此**沙箱边界是项目根、不是节点 worktree ⇒ 节点间写隔离只能靠租约准入 + 收工逐文件对账** |
| A6 | **证据复用判据** | **默认整树失效**。只对"**已在冻结的验收清单里声明 `inputs[]`（路径 + sha256）**"的验收开放细粒度复用；**空数组 `inputs: []` 视为未声明**；**变更路径必须由插件用 `git diff` 自算，不得取自角色**；`inputs[]` **必须覆盖非 git 跟踪的输入**（夹具 / env 文件按 sha256 绑定），否则声明天然不完整。等价条件 = **五项闭集**：**候选树 + 命令 + 环境摘要 + 沙箱/权限模式 + 外呼宣言**；**它是"必须比对"的下界，不是"只看这些"的上界**——插件已采集到的其它身份字段（解释器 / 工具链 / 依赖目录等）若不同，至少告警并进"证据质量"计数，不得静默放行。**换人执行不改变复用条件**。`inputs[]` 的**完备性不可证明**：复用时必须标注 "基于声明输入集、完备性未证"，且该标注计入体检报告的**证据质量**节 |
| A7 | **失败对比粒度** | base↔候选的红集对比必须同时给出失败的**名字与位置/类型**（断言点、异常类型、失败因）；只有名字相同**不足以**判定"无新增" |

> 这五条对应的正是昨晚最贵的几类返工：**旧结论被挪到新代码上、审查通过的不是最终合并的那一版、路由层守卫与真实事务之间有时间差、合并后失败被"再改改"掩盖**。
>
> **A2 的运行前提口径（2026-09-20 修订，含方向澄清）**：这条的实质不是"禁止外呼"，而是"**运行前提必须声明，且实际与声明一致**"——包括外部调用的有无、真实/离线模式、树与环境身份。
> - **DSH 平台事实**：沙箱是**纯文件效果**策略（`Network and process visibility are outside this vocabulary.`），**没有网络平面、也没有开关** ⇒ "禁止真实外部调用"**不可强制**，本文不要求它。
> - **两个方向，严厉度不同**（不是对称的）：
>   - **声明"需要真实外部调用"、实际没有** ⇒ **判 `unqualified`**。这是**致命方向**：你以为验了真链，其实没验。一次真实事故就是如此——栈没导出在线开关，被离线闸门**静默拦截数小时**，表面只是"连接错误 / usage=0"。
>   - **声明"不需要"、实际发生了** ⇒ **告警 + 记录，默认不阻塞**。仅三种情形判不合格：① 该断言本身就在测"不外呼"；② 该调用有**外部副作用**（邮件 / 推送 / 部署 / 扣费）；③ 该场景明确依赖"可离线运行"这一性质（CI、无网环境、需确定性复现）。
>   - 补充说明：为何后者值得记录但不值得硬拦——它的代价通常是**配额与少量成本 + 变慢 + 可能 flaky**，而不是"结论错"；但它会让该次运行的**运行条件不可复现**，因此至少要可追溯。
> - 证据必须区分四态：`声明需要·已发生` / `声明需要·未发生（不合格）` / `声明不需要·未发生` / `声明不需要·已发生（告警）`；无法观测时标 `unverified`，**不得把"未验证"写成"已验证"**。尽力而为的代理封堵可做，但必须标 best-effort，不得当作强制证明。
> - **一般化（2026-09-20 定稿）**：这条不只管外部调用——它覆盖**任何"运行前提"**：**树身份、环境、模式、外呼有无**。合起来是一条通用规则：**任何运行前提都必须"声明 + 采集 + 一致"，才配叫证据**。这条同时吸收了 N3（在错误 worktree / 错误 PYTHONPATH 下跑出的结果一律判不合格）。

### B. 架构守卫（防止"已经查出来的问题再犯一次"）

**要达成的效果**：已知的架构缺陷**不可能因为某次任务整备"没想起来"而被绕过**。

| # | 能力 | 说明 |
| --- | --- | --- |
| B1 | **活跃架构缺陷登记** | 一份机器可读的登记（每条：id / 一句话症状 / 受影响事实与路径 / 违反的不变量 / 权威引用 / 上次核实时间）。**只存活跃项**，已解决即移出（历史交给 git）；总量设上限，超限要求先做清理 |
| B2 | **强制摄入** | 判据是**机械谓词**：**相关缺陷候选非空 ∧ 未逐条表态 ⇒ 拒；候选为空 ⇒ 过**。（原措辞"不允许空列表直接通过"有歧义，已按此更正：**不是要求列表永远非空，而是有候选就不能不表态**。）**时机 = `→ prepared`（准备阶段），不是 freeze**：它的作用是在**动手前影响动手的方式**；放到 freeze 就从"事前约束"退化成"事后签字"，而且不申报候选的节点永远不会被摄入。**并把"相关缺陷集 + 每条处置"纳入候选身份的决策快照**——这样 freeze/merge 时若相关缺陷集变了，由 A1 自动失效（两侧都覆盖，且不新增机制）。处置允许**一句话理由**（弱档，不要求论证） |
| B3 | **所有权与事务声明** | 节点若声明"我要写某个业务事实"，必须同时声明：该事实的 **canonical owner**、**允许的写路径**、**现存其它写点**、以及这次写活的**事务边界**（哪些写必须原子、提交点在哪）。**canonical owner 未定、或引入第二个活跃写者而无裁定 ⇒ 拒绝进入可开工状态**，要求先出架构裁定 |

> 背景：UCBIP 在 2026-09-15 就做过一次完整架构调查（有 file:line、有复现脚本），但 09-19 的任务卡**只引用了现象、没有引用那份调查**；同一个缺陷被当成"实现问题"重新发现了一遍，并因此产生一轮返工。

### C. 上下文卫生与交接胶囊（**不含 token 配额**）

> **Owner 明确保留意见**：给 agent 限定 token 预算不太可能加快开发。所以这一组**不要求配额**，只要求**可观察 + 可交接**。

| # | 能力 | 说明 |
| --- | --- | --- |
| C1 | **交接胶囊** | 任何角色在任意时刻能产出一份胶囊：节点 id / 当前阶段 / **最后确认的效果**（commit、tree、外部调用 id）/ 工作区状态（worktree、是否 dirty）/ 占用资源（进程、端口、租约）/ **我方造成的已知失败** / 阻塞前提 / **下一步（一条祈使句）** / 证据指针 / **不可重复执行的外部动作** |
| C2 | **可独立续做** | 一个新的会话，只读 **胶囊 + 节点记录 + git** 就能继续该节点：**不需要读旧对话记录，也不需要读项目的大文档** |
| C3 | **上下文可观察** | 能报告每个会话的上下文增长（观测，不强制），让协调者能在代价变大前轮换会话 |
| C4 | **消息不承载事实** | 协作消息只承载**指针与唤醒**（节点/决定 id + 原因码），事实必须先落在记录里；**任何正确性条件都不得依赖消息成功送达** |

> 背景：昨晚 99% 的花费是"反复重读上下文"，平均每次调用 357K 上下文；最长的一个会话 1,316 次调用、峰值 936K。真正需要的是"把工作切成有界单元 + 把状态放进交接物"，不是限额。

| # | 缺陷（原文口径） | 我要的效果 |
| --- | --- | --- |
| D1 | **重启后角色变空壳**：首波拉起的角色重启后仍是完整的；**懒加载的、以及重激活时重建的**角色重启后掉到只剩宿主工具（读不了文件、改不了代码），且**不报错、没有代码会发现** | 让"每个角色都带着**持久**的完整身份出生"成为**构造性保证**，而不是路径依赖；重启后必须可核其实际挂载的组合 |
| D2 | **只读角色被沙箱拒绝 → 发起一个没人能回答的审批 → 回合永不结束**（停摆兜底只看"运行中→空闲"，抓不到） | 无人值守下**不允许出现无法结束的回合**：要么把提权/审批**路由给指定的应答者**，要么把"永不询问"钉到**所有**建会话路径（现在只覆盖首波） |

### E. 权限与请示（Approval & Escalation）

> 背景事实：DSH 有**三档权限**（只读 / 工作区修改 / 完全权限）；**所有会话一律在项目根启动**，worktree 只是起始点而非独立沙箱；**禁止弹"需要人点确定"的卡片**。
> 这一组解决"无人值守时，权限与请示怎么办"——它是"无人值守不死"的另一半。

| # | 能力 | 说明 |
| --- | --- | --- |
| E1 | **权限预分配；提权请求不得挂起** | 角色权限档位在**派发时由编排者钉死**（只读角色永远只读；实现者给"工作区修改"）。**验收断言**：运行期任何提权请求都**不得使回合悬挂**，必须以**确定性拒绝**收束，并留下可判定事实（请求 id / 结果 / 原因码）。被拒后由编排者决定**改派**给有写权的角色，或调配置后**重派**。**不要用"问一句"解决权限问题**。（不要求"模型不会尝试"——那不在平台能力内，见 §4.11） |
| E2 | **三类请示各有去向** | ① **技术分叉** → oracle（异质、独立判断）；② **范围/依赖/资源** → driver；③ **产品/权限/风险接受** → **不进问询**，进**决策队列**，且**只暂停依赖该答案的最小步骤**，其余继续；④ **安全/凭据/不可逆** → 立即停止相关动作并通告 |
| E3 | **带默认值的请示（关键）** | 任何请示必须自带**"若不回答，我就按 X 做"的默认值 + 截止时间**；到点**用默认值继续**并留痕（可被覆盖），而不是挂起。**例外（不可默认，到点停在原地）**：权限变更、数据处置、不可逆外部动作、发布资格 |
| E4 | **默认权限档 = "工作区修改"** | "完全权限"只能由角色声明 + 编排者批准，**不得作为默认**（默认全权等于丢掉唯一的写面护栏） |

**与 D2 的关系（本节修订上一版）**：D2 上一版写作"到点拒绝该动作并继续"；现修订为**分型**——**可默认类**到点用申报默认值继续（不压制可自主范围内的推进）；**不可默认类**到点**停在原地**（不得代为决定）。

### F. 独立性：设计门必须由独立会话作出

| # | 能力 | 说明 |
| --- | --- | --- |
| F1 | **设计门必须由独立会话作出（F1′ 定稿）** | ① **设计级审查（方案门）必须由独立会话作出**——fresh context、非设计者本人，且**只拿得到记录与产物、看不到作者的推理过程**；② 节点记录写明**设计者与审查者各自的 session id 与 model id**（零成本，便于将来复盘"某类返工是否与模型相关"）；③ **部署里存在第二个可用模型时优先使用**（记 `satisfied`）；没有时记 `degraded`、**不阻塞**，但**必须在定期报告里可见**（不得静默）；④ 普通实现审查**不强制**。依据：本季最贵的两处结构性缺陷（写守卫 TOCTOU、单价 canonical 唯一 producer）都是**设计层面**的错，同族审查未发现；另一处现场证据——上轮 E2E 里 `difficulty-reviewer` **从头到尾是 `reserved`、从未物化**，该车道设计**根本没被独立审查过**。**补充硬约束**：未物化的角色**不得被记为"已参与"**；设计门若未实际发生，记录必须写 `gate_not_run`，**不得记 `satisfied`** |

### 2.1 三处整合补丁（跳组，不写会从缝里漏）

1. **A1 × E3：override 来得太晚会怎样。** override 在候选**冻结之后**才到 ⇒ 候选 generation +1、旧证据与旧审查全部失效；**已合并**才到 ⇒ 只能走 A4 的"合并后终态"（精确 revert 或新建修复节点），**不得回改历史**。
   （说明：这**不需要新机制**——`decision_snapshot_hash` 已进候选身份，override 自动使它过期；只需把推论写明。）
2. **E2 的"决策队列"是一条记录，不是一句原则。** 字段：`question / default / deadline / blocks:[nodeId] / state / owner / resolved_by`。插件只强制一件事：**`blocks` 里的节点不得冻结或合并，其余一切继续跑**。长龄项计入定期报告；**发布资格类只能由人关闭，不允许被默认值消化**。若默认值已生效而答案后到，记录必须写成 `default_applied_then_overridden`（历史诚实）。
3. **收工对账必须有豁免集，且豁免集必须被打印出来。** worktree 在项目内 ⇒ 它自己就是未跟踪内容；`orchestra/`、工具缓存同理。因此对账的"声明写入面"必须带**显式豁免集**（`.worktrees/`、`orchestra/`、明示工具缓存），并写入 `.git/info/exclude`；**对账报告必须打印当次豁免集**——否则它会静默长大。

## 3. 验收（怎么证明"做好即可用"）

### 3.1 一条端到端交付（必须真实，不许 fixture）

在**一个真实 git 仓库**上跑完整条：建队（宪章批准）→ 冻结一个节点（含验收清单）→ 实现者产出候选 commit → 独立审查通过 → **经合并门 + CAS 合入集成分支** → 合并后检查 → 收口。
**除最初一次的宪章批准外，全程无人介入。**

### 3.2 必须被拒绝的负例（这些比正例重要）

| # | 注入 | 期望 |
| --- | --- | --- |
| N1 | 审查通过后修改候选 | 合并被拒，原因明确指向"审查结论属于旧候选" |
| N2 | 合并门预检后，集成分支被别的节点推进 | 不得沿用旧预检：重新预演；成立则合、不成立则拒 |
| N3 | 在错误的 worktree / 错误的 PYTHONPATH 下跑验收 | 证据判**不合格**；该验收项视为无有效证据，不得当作通过 |
| N4 | 合并后检查失败 | 记为"已合并但验证失败"的终态；**不许**把原节点改回进行中 |
| N5 | 节点写入的事实有第二个活跃写者且无裁定 | 准备阶段被拒，并给出**类型化**原因 |
| N6 | 实现者会话在做一半时被杀死 | 新会话只读"胶囊 + 节点记录 + git"即可继续；**不读旧对话** |
| N7 | 重启运行时 | 每个角色（首波 / 懒加载 / 重激活）都仍有完整身份，且其实际挂载组合**可核对** |

### 3.3 给"今晚跑测试"的三条优先项

1. **重启 → 角色身份回归**（首波 / 懒加载 / 重激活各一个角色；重启后核实际挂载的组合，而不是问会话自己）；
2. **只读角色的沙箱拒绝路径**（断言它**不发起审批**，且回合能正常结束）；
3. **批准后的受治理端到端**（用已备好的探针拓扑，看是否真的按后端类型建成并跑到 Closure）。

## 4. 约束与非目标

1. **优先减法。** 凡是 DSH 原生已有的设施（预设名册、A2A/委派、应答者、组合投影、原生子代理、Workflow/Goal 等），优先替换掉插件自建的那一份，而不是在自建之上再加一层。这条比新增功能更重要。
2. **不引入 token 配额。** Owner 明确保留：限额不认为能加速开发；本文件只要求"可观察 + 可交接"。
3. **不新增 UI 需求。** 本文件不涉及界面。
4. **保持通用。** 交付层要对任意 git 仓库成立，不得绑定 UCBIP 的目录结构、测试框架或语言。
5. **规则要"拒绝"，不要"劝"。** 每条规则要么能被系统拒绝（带类型化原因），要么就不要写进文档——避免"文档承诺 vs 实际行为"的悬空。
6. **不要照抄本文的实现建议。** 本文只给能力与验收；DSH 侧有什么原生能力，请你自己查并选择。
7. **未验证的不要写成现状。** 沿用仓库既有纪律（"尚未在代码中落地的部分不得表述为现状"）。
8. **机制准入规则（一条机制，一个已付过成本的故障）。** 任何新增机制必须指名它防止的**具体故障**，且该故障必须**已经真实付过成本**（有一次现场实例）。指不出故障、或理由只是"听起来更稳 / 更规范 / 更工程化" ⇒ **不做**。此规则同时约束需求方与实现方——**用来防止越做越像确定性流水线**。
9. **实现必须是大头。** 计划期与验证期的机械负担**不得把实现挤成小头**。落地方式：节点记录带上"计划 / 实现 / 验证"三段的可观察配比（轮次或 token 均可，**不要求精确**）；**若计划+验证长期超过实现 ⇒ 视为机制过重，回头删机制**。
10. **不要求任何"开工前完备度"。** 不要求开工前写完验收标准、不要求开工前做完所有权声明、不要求开工前登记所有新概念。（验收清单的冻结点是**"申报候选之前"**，不是开工前。）
11. **不得声称清单（平台事实与证据边界）。** 以下几条**不得写成更强的现状**：
    ① **"运行期不接受提权"**只保证"提权请求不挂起 + 确定性拒绝 + 留痕"，**不保证模型不会尝试**（DSH 工具结果仍会提示可申请提权）；
    ② **"禁止真实外部调用"不可强制，也不是本文要求**——本文要求的是"**运行前提声明 + 实际一致**"，且两个方向严厉度不对称（见 §2.A 口径注）；
    ③ **"换会话 ≠ 换模型"**——独立会话买到的是"没有作者的上下文污染"，**买不到**"不同的先验知识"；不得把前者说成后者；
    ④ **"宿主采集"**只保证"判定字段不是角色自报的 + 与声明一致"，**不保证**被测程序内部没做别的事（威胁模型之外）；
    ⑤ **"合并门通过"**不保证代码是对的，只保证"审查、证据、写面范围、候选身份都绑定在这次候选上"；
    ⑥ **"证据复用"**不保证旧读数适用于新语境，只保证"判定所依赖的条件（树、命令、环境）逐项可比"。
