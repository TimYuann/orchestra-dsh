## 2. 需要 UCBIP 确认的三处（**动了他们的口径**）

### 2.1 元规则二：成本比率**只作报警**，删除改走"每周机制复查"

- **原表述**（他们的）："若计划+验证长期超过实现 ⇒ 视为机制过重，回头删机制。"
- **问题（Pro 指出）**：比率**可以被做漂亮**——把设计记成实现、故意拖长实现、拆节点都能压低它；反过来，**一行修复配大量验证反而受罚**（比率越"好"，越说明该做的验证被省了）。
- **改成**：比率**只作报警**；删除判据走**每周复查**，且**三条同时成立**才删：**连续两窗有成本** + **无独一拦截**（拿掉它不会丢任何独有的拦截）+ **原故障已有等强覆盖** ⇒ **下窗必须停用或合并，并绑定执行人**；**"没有故障发生"本身不构成删除理由**。
- **为什么仍然满足你们的规则一**：删除不是"因为没出事"，而是"**原故障已被别的东西等强覆盖**"——判据仍然是"指得出故障"。

### 2.2 档 0 与"轻量档"的关系（合成三档）

- 你们说的**轻量档**：仍会进集成分支 ⇒ 候选身份 / 合并门 / CAS / 宿主采集**四样不可裁剪**。**保留**。
- Pro 说的**"不启用"**：按**交付用途**判，而不是按改动行数——机械谓词全部满足（**执行会话 = 1、交接 = 0、依赖边 = 0、输出仅聊天、合并/发布/可复用 PASS 全部禁用**）⇒ **整个交付层关闭**；首次申请任一交付动作即**重新准入**，且**不追认此前产出的 PASS**；**原有权限与外呼审批不随豁免关闭**。
- **两者不冲突**，是两件事：**档 0 = 没有交付对象**（例如"解释一段用户给的函数"）；**轻量档 = 有交付对象但流程从简**。合并后见契约 §1.2。

### 2.3 体检报告四节要并入 Pro 的六项早期信号

| 信号 | 对应先坏点 | 并入哪一节 |
|---|---|---|
| 未知前提获 PASS 数 | 证据采集冒充输入绑定 | ① 降级 |
| 干净重放差异率 | 同上 | ① 降级 |
| 交叉越界数 | 租约被告警绕过 | ② 豁免集 |
| 豁免命中活跃租约数 | 同上 | ② 豁免集 |
| ref / 节点账本不一致数 | 归并与记账撕裂 | ③ 决策队列（账实不符项） |
| 已合并节点被重新派发数 | 同上 | ③ 决策队列（账实不符项） |

（其余四节内容不变；"缺任一节即报告无效"的断言不变。）

## 3. 无需确认、建议自动接受的

§1 的 **B1–B7**：全部是**实现级**修正，不改变需求的能力集合，只把口径写准（候选身份的措辞与逃生门、复用边界、E3 的授权边界、三个先坏点的实现约束）。其中 **B3 是我方提案被推翻**，见 §4。

## 4. 撤回记录（审计痕迹）

- **我方原提案**：把证据复用的等价判据从"整棵树"细化到"**每条验收声明的输入范围**"，理由是"改一个字符不该让二十条验收全部失效"。
- **被推翻的理由**：**子树相同 ≠ 输入相同**——共享配置、脚本、依赖、工具链都可能改变结果；更关键的是，**声明"我只依赖这里"的是角色，而角色自述不能作为判据**（这违反我们自己的原则：能机器推导的不许角色填）。
- **替换方案**：默认整树 + 运行条件；**只对"已有工具能核验完整输入范围"的验收开放细粒度复用**；未知依赖不复用；**不为此自建依赖分析器**（省下的几次测试不值得多一个要维护的依赖分析器）。
- **保留的价值**：候选身份那条的**逃生门**仍在——"不交新改动就仍交旧候选"，加上"只重跑无法证明不受影响的验收"，原提案想解决的"一字改动全盘重跑"问题，用**更安全的方式**解决了。

## 6. v1.1 → v1.2（UCBIP round-7 定稿前五条，**已全部采纳**）

| # | 变更 | 论据 | 落点 |
|---|---|---|---|
| 1 | 每周复查**必须留痕（含"本周无候选"）**；且 **"比率已连续两窗报警 + 复查连续 N 周无候选"本身必须成为告警** | 一条只活在纪律里的自我缩减规则会安静地死掉；**"报警了但没人动"正是它死掉时的形状** | 契约 §1.8 |
| 2 | "未知前提获 PASS 数 / 干净重放差异率"从 ① 降级**独立成第 ⑤ 节「证据质量与前提绑定」** | ① 的含义是"缺能力、知情接受"，这两项是"**证据不可靠 ⇒ 停下修证据**"；混在一节，读者分不清"可接受的现状"与"必须处理的缺陷" | 契约 §1.9⑤ |
| 3 | "ref / 账本不一致数、已合并节点被重新派发数"从 ③ 决策队列**移入「立即阻断清单」** | 这是**账实不符**，按双方已确认的"停机报账"规则属**阻断项**；放进会变老的队列会静默累积 | 契约 §1.9 阻断清单 |
| 4 | **B1 的"不受影响"与 §1.4 复用判据同源**：以"**可核验的输入绑定 + 路径交集**"为准；**没有输入绑定的一律默认"受影响"**；不得由角色或审查者一句话判定 | 我方原文里 B1 的逃生门**比 §1.4 的判据更松**，属**内部不一致**（由 UCBIP 发现） | 契约 §1.3 |
| 5 | B5-4 补**解除路径**：不可重复动作"结果未知 ⇒ 阻断"的解除**只能由人节点作出并留痕** | 否则"结果未知 ⇒ 永久阻断 ⇒ 节点永远完不成"，那是**另一种悬挂** | 契约 §1.5-4 |

**结论**：round-7 之后 UCBIP 侧**无新增或修改**；**契约 v1.2 即双方一致版本**。
