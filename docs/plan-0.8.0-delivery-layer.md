## 0. 三条不可动摇的设计约束

1. **门只能设在"插件拥有的动作"上**：准入（开工/冻结/合并/归档）、账本与节点记录写入、验收执行、git 操作。对任意文件写入**只能事后对账点名**——**唯一例外**：越界触及他人**活跃租约**时必须阻断冻结/合并（§1.6）。
2. **事实的作者永远是插件，会话只提供材料**：事实类字段（候选身份、commit/tree、退出码、环境、锁面、基线、账本）只由插件写；会话只能写意图与解释，**永不作为门的判据**。
3. **严格压在"宿主能重算"的地方**；需要再跑一轮会话才能判的，宽和 + 留痕 + 交给人。

### 1.1 预设私有根的部署步骤（一次性，每个 profile 一行）

**本部署里没有可改的 `agent-presets` 行**——它由 `@deepseek-ai/dsh-web-app` 的 bundle 层 patch insert 进来（`cordis.patch.yml:481`），两个 profile 自己的 patch 文件当前是 `[]`。

**正确写法：在 profile 的 patch 里做「单跳 override」**——命中那一行并**整体替换它的 `config`**：

```yaml
- id: agent-presets
  config:
    default: standard          # 必须自带：补丁是"按键浅替换"，少写就只剩 roots
    roots:
      - path: ~/.dsh/orchestra/catalog-presets
        trust: system
```

- ⚠️ **不要用"两跳"写法**（先 insert 一个 group、再往组里 insert 一行）：实测会插出一条**新的** `agent-presets` 行，与 bundle 原行**并存两条同名条目**，而**原行并未被修改**。
- 依据：补丁引擎允许后一层的 patch 命中前一层 insert 的行（`@deepseek-ai/cordis-plugin-include/lib/index.js:70-84`）；浅替换在 `:100-103`（**实测复现**：`config` 少写 `default` 就只剩 `roots`）。
- **实现前必须再确认一次**：用同样的内存实测确认「**profile 的 patch 层在 bundle 的 patch 层之后应用**」——若顺序相反，单跳会只报 `entry not found` 警告而静默不生效。
- 落点：`~/.dsh/profiles/{web,dev}/` 的 patch 文件（做法参照 `DSH-INTEGRATION.md`）。**新增根需重启实例**；往已在扫描的根里放/改文件即时可见。
- **验收**：三条激活路径（首波 / 懒加载 / 重激活）都必须能解析到该根 —— 由 **N7** 从外部核实际挂载的组合。

### 1.2 节点分级（**不可含糊**）

| 档 | 判据 | 必须保留 | 可裁剪 |
|---|---|---|---|
| **档 0（关闭）** | **机械谓词全部满足**：**无任何交付动作**（合并 / 发布 / 可复用 PASS 全部禁用）、**交付型交接 = 0**、**交付型依赖边 = 0**、无插件可见的产物引用。**不限制聊天会话数**，**不限制纯聊天会话的交接与依赖**（它们不构成交付） | ——（整个交付层关闭） | 全部 |
| **轻量档** | 仍会**进集成分支**，但裁剪了下述项 | **候选身份 + 合并门 + CAS + 宿主采集读数**（**四样不可裁剪**） | 设计门、架构守卫、写面租约（**仅单写者时**）、胶囊 |
| **标准档** | **默认** | 全部 | —— |

- **分级必须显式声明在节点记录里**；默认 = 标准档；轻量档必须在任务卡里**写明理由**（缺理由即校验失败）。
- 档 0 首次申请任一交付动作 ⇒ **重新准入**，且**不追认此前产出的 PASS**；**原有权限与外呼审批不随豁免关闭**。
- **防漂移**：轻量档与档 0 的**比例必须进定期报告**（§1.9③）。

### 1.3 候选身份与复审判据

- 候选 = 一个 commit（含 tree）+ 冻结的验收清单 + 冻结的决策集；**冻结点 = 门运行之前**（不是开工之前）。
- **失效的是"新候选的放行资格"，不是历史观测事实**：工作区改字**改不掉已冻结的 commit**。
  - **不交新改动** ⇒ **仍交旧候选**（把闯入的改动撤掉，或就交那一版）；
  - **必须交新改动** ⇒ 独立审查者**补审差异 + 重新确认证据适用性**，**只重跑"无法证明不受影响"的验收**，再签发新判决。
- ⚠️ **"无法证明不受影响"的判据与 §1.4 同源**（round-7 修正：此前 B1 的逃生门比 §1.4 的复用判据更松，属内部不一致）：**以"可核验的输入绑定 + 路径交集"为准**；**没有输入绑定的一律默认"受影响"**。**不得由角色或审查者用一句话判定"不受影响"。**
- **硬线**：**改验收断言或决策语义，不得把旧 PASS 换个版本号继续用**。

### 1.4 证据复用

- **默认保留"整树 + 运行条件"**；**只对"已有工具能核验完整输入范围"的验收开放细粒度复用**。
- **不接受角色自述"我只依赖这里"**（子树相同 ≠ 输入相同：共享配置、脚本、依赖、工具链都会改变结果）。
- **未知依赖一律不复用**；**不为此自建依赖分析器**。
- **历史外呼读数不能证明"本次发生了真链"**——外呼观测必须**逐次采集**。

### 1.5 E3「带默认值的请示」五条收紧

1. **默认值只能落在既有授权内**，**不得由 agent 临时自授决定权**（不得默认"我将越界写"或"我将允许外呼"）；
2. 继续范围**必须可撤销、且有明确成本上限**；**不得把默认值当"已批准事实"传给下游**；
3. **迟到答案必须形成新决策并处理受影响工作**，不得只记一笔就冒充"一直如此"；
4. **不可重复的外部动作结果未知时必须停**（`do_not_repeat` 的 `unknown/attempted` ⇒ **阻断**，不是告警）。**解除路径（round-7 补）**：解除**只能由人节点作出并留痕**——否则"结果未知 ⇒ 永久阻断 ⇒ 节点永远完不成"，那是另一种悬挂；
5. **截止时间必须由宿主持久化 + 有恢复触发**——没有持久化的到期判断与唤醒，"到点继续"是空话。

### 1.6 写面租约与对账

- **准入硬拦**：写面重叠的节点不得同时开工/冻结。
- **收工对账**：拿申报范围对实际改动，范围外**点名**（不阻塞）——**唯一例外**：**越界触及他人活跃租约 ⇒ 必须阻断冻结/合并**，**豁免不能取消这个冲突**。
- **豁免集**：显式声明在配置里；每条带**理由 + 加入人 + 加入时间**（缺理由即校验失败）；**每次对账报告必须打印当次全量豁免集**。

### 1.7 Pro 审核指出的三个"最先坏的点"（实现时必须照做）

1. **证据采集冒充输入绑定**：未跟踪夹具参与测试而 HEAD 不变；宿主执行 ≠ 环境封闭。
   ⇒ **验收必须从"冻结快照"执行**（`git worktree add --detach <tree>` 或等价），**额外输入（夹具 / env 文件）按哈希显式绑定**；外呼观测不完整记 `unknown`，**关键前提未知不得判合格**。
2. **写面租约被告警绕过**：见 §1.6 的例外。
3. **归并与记账撕裂**：树比对不是 CAS，`merge-tree` 只计算合并树。
   ⇒ 目标 ref 更新必须**原子核对预期旧值**（`git update-ref <ref> <new> <expected-old>`）；并定义"**ref 已推进、记账前崩溃**"的**幂等恢复**，否则重启会误判尚未交付。

### 1.8 元规则二的执行方式（每周机制复查）

- **成本比率（`ratio{plan, implement, verify}`）只作报警**，不直接决定删什么（可被"把设计记成实现 / 故意拖长实现 / 拆节点"做漂亮；一行修复配大量验证反而受罚）。
- 改为：**按根任务归集实际成本**（含失败、取消、返工）+ **每周固定复查**。
- **删除判据三条同时成立**：**连续两窗有成本** + **无独一拦截**（拿掉它不会丢任何独有的拦截）+ **原故障已有等强覆盖** ⇒ **下窗必须停用或合并，并绑定执行人**。
- **"没有故障发生"本身不构成删除理由**（删除依据是"原故障已被等强覆盖"，判据依然是"指得出故障"）。
- **（round-7 补）复查必须留痕，含"本周无候选"也必须记录**；且 **"比率已连续两窗报警、而复查连续 N 周无候选"本身必须成为告警**——一条只活在纪律里的自我缩减规则会安静地死掉，而"报警了但没人动"正是它死掉时的形状。
  （例：同一冻结边界反复人工抄核同一 hash ⇒ 删重复抄核，**不是**删版本绑定。）

### 1.9 体检指标 = 独立验收断言（**五节 + 立即阻断清单**）

**定期报告必须固定输出五节 + 一份阻断清单，缺任一节即报告无效**：

| 节 | 内容 | 这一节的含义 |
|---|---|---|
| **① 降级** | 设计门 `degraded`/`gate_not_run`、外呼 `unverified`、写面只能对账 | **"我们缺这项能力，知情接受"** |
| **② 豁免集** | 当次全量 + 每条理由 / 加入人 / 时间 | 声明过的例外，可审计 |
| **③ 决策队列** | 年龄、可默认类的结案状态、**轻量档与档 0 比例** | 待决与分档漂移 |
| **④ 三段配比** | `plan / implement / verify` + **每周机制复查结论（含"本周无候选"）** | 机制是否过重 |
| **⑤ 证据质量与前提绑定** | **未知前提获 PASS 数**、**干净重放差异率**、**交叉越界数**、**豁免命中活跃租约数** | **"我们的证据不可靠 ⇒ 停下修证据"** |

**⑤ 必须与 ① 分开**（round-7 修正）：① 是"缺能力、知情接受"，⑤ 是"必须处理的缺陷"；混在一节，读者分不清"这是可接受的现状"还是"这是要马上修的"。

**另附「立即阻断清单」（不进会变老的队列）**：**ref / 节点账本不一致数**、**已合并节点被重新派发数**——这两项是**账实不符**，按双方已确认的"停机报账"规则属**阻断项**；③ 队列只记"谁在何时把账平了"。

理由：这套系统整体是"禁止与登记"，**这五节是唯一能发现"机制本身正在退化"的窗口**。

## 3. 阶段

### P0 · 事实层与三处收口（先做）
D1 角色身份持久（S1 + S3 + **全路径核对实际挂载的组合**）；D2 回合不悬挂（钉死覆盖所有路径 + 宿主受理者 + 截止时间）；D3 归档先停后记；**E 组**（E1/E2/E3/E4 + §1.5）。
**退出判据**：N7 + D2-a/b/c 三条断言 + 需求 §3.3 第 1、2 条。

### P1 · 证据层
极薄执行层（`(node_id, check_id)` → 冻结清单 → **冻结快照执行** → 固定 cwd/env → 采集 → 结构化落盘）；**运行前提一致**（§1 的四行不对称 + `unknown` 规则）；基线采集与差集（名字 + 位置/类型）、`stale_baseline`。
**不做**：沙箱实现、CI 集成、并发调度、环境 profile 完整建模、**自建依赖分析器**。
**退出判据**：N3 + 基线差集与人工对账一致 + **"声明需要真链却未发生"能被判不合格** + **未跟踪夹具不会让证据冒充输入绑定**。

### P2 · 交付层
写面租约（准入硬拦 + §1.6 例外）；节点记录（插件写、不进 git、非插件可读、`<主 worktree>/orchestra/nodes/<node-id>.json` + `schemaVersion` + 纯 JSON）；候选身份与复审（§1.3）；证据复用（§1.4）；**F1′**；合并门（`merge-tree` 预演 → `rev-parse HEAD^{tree}` 比对 → **`update-ref` 带预期旧值的原子更新** → 崩溃幂等恢复）；豁免集；决策队列（`question/default/deadline/blocks/state/owner/resolved_by` + **宿主持久化到期与唤醒**）。
**不做**：自己遍历文件算树；用 `index.lock` 判写者；因未跟踪文件整批拒；**普遍细化到子树**。
