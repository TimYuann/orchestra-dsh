### H.1 F17 四段表是否真穷尽（门第 3 轮只验这一项）

**旧表的漏洞**：四条断言的前提互相重叠——"`ref == expectedOld`"与"已有同 attemptId"可以同时为真，而两段给出的动作**相反**（重做 vs. 什么都不做）。`ref == expectedNew` 与"已有同 attemptId"同样可以同时为真。

**新表为什么穷尽**：

1. **判定按行序，命中即停**，所以重叠不再是歧义，而是**优先级**问题——`attemptId` 已记账是终态事实，**优先于任何 ref 观察**，因此它排在第 ① 行。
2. **前四行按 `ref` 的取值划分为互斥且穷尽的四类**：`== expectedNew` / `== expectedOld` / 第三个值 / （在 ① 已排除"已记账"的前提下，这三种覆盖全部可能）。
3. **第 ⑤⑥ 行按 `intent` 的可读性补全**：可解析但不在前四类 ⇒ 已被前三类覆盖；不可解析 ⇒ ⑤；不存在 ⇒ ⑥。**没有任何输入会落到表外**。
4. **写入原子性（H-2）保证 ⑤ 是可达但稀有的分支**——`rename` 之后不可能出现半份文件，所以 ⑤ 只覆盖"`rename` 之前就被中止"这一种情形，而且**它明确不猜**。

**判定脚本必须覆盖六行各一个用例**（写进 §4.2.1）：
- **① vs ③ 的重叠用例**：`ref == expectedOld` **且**已有同 attemptId ⇒ **必须走 ①**（记 `ledger_ref_mismatch`、**ref 一动不动**），**不得**走 ③ 重做。这是 H-1 的直接回归测试。
- **⑤ 截断用例**：在 `intent.json` 里写半份 JSON ⇒ 走 ⑤、不崩、**不按半份内容继续**。
- **⑥ 正常路径**：无 intent ⇒ 无动作。
