# 0.8.0 执行协议（driver 侧）与剩余开发地图

> **这是什么**：A2A 传输不可用期间，**driver ↔ Implementer ↔ Owner 一次往返的契约**。
> **不是什么**：不是新机制、不是新闸、不新增记录字段、不写一行运行期代码。全文没有一个字段是"为了协议本身"而加的。
> **传输无关**：A2A 恢复后本文不变，只是"人"换成 `a2a_send`。所以本文不依赖人的判断力。

---

## 1. 传输定律（基础设施没了，剩下的那部分哲学）

1. **文件系统是总线，人只是中断线。** 两个会话共享同一个仓库 ⇒ 边只携带**指针**，不携带载荷。一次转发 = 一行"去读 X，按 Y 判"。
2. **每条边自足。** 接收方不共享发送方的历史：结论 / 证据 / 未做未验证 / 一条可判定的指令 / 分支决策表。缺任一栏，接收方就得回来问——那是多花一次跳。
3. **跳数是唯一稀缺资源。** 所以**预登记**分支决策：一次往返里把"如果 A 就…如果 B 就…"全部答完。预登记还有一个副作用是**必需的**：规则在看到结果之前写定，才不构成"作者给自己打分"。
4. **星形拓扑。** 所有边都经 driver。不得设计任何需要角色与角色直连的环节——即使 A2A 恢复，原生委派也只授权直接父边，这条约束不会消失。
5. **检查不是轮次；只有争议计数。** 机制没命中它自己的期望码 = **缺陷**（按 fault_ref 走），不是审查意见。只有"设计异议"计入审查轮，按**问题 id** 计数，上限 2，之后交 Owner 指定的独立会话。
6. **每个节点必须有确定终态。** 要么产出下一跳，要么产出一条写进 `docs/open-questions.md` 的问题 + 明确停点。**"等 driver 回话"不是终态**（无人值守不变式在有人的版本)。
7. **记录在文件里，不在聊天里。** driver 会被压缩：任何三轮后还重要的事，必须落 `docs/`，且与被描述的改动同一个 commit。
8. **driver 不动手。** 发现缺陷 ⇒ 记录 + 带 fault_ref 交回；不由 driver 修，也不由 driver 代写代码或代写结论。

## 2. 一次返回怎么处置（**预登记：在看到结果之前写定**）

### 2.1 driver 收到任何返回后的固定动作

1. `git status --porcelain` —— 树必须干净；记下**候选 commit**（锚点是 commit + 符号，不是行号）。
2. 在**独立 worktree** 里复跑：`git worktree add --detach /tmp/orch-verify-<sha> <sha>`。**绝不在在飞的工作树上跑闸**（Implementer 可能正在写，红/绿都无意义）。
3. 逐项对 **G-P0 ①–⑨**，**按各自期望码**判（正常模式 **0**、`--self-test` **1**）。
4. 结论写 `docs/review-rounds-ledger.md` + 一份 `docs/` 记录；本地 commit（**推送等 Owner**）。
5. 产出下一跳（含分支决策表）。

### 2.2 分类表（穷尽且可判）

| 类 | 判据（机械） | 处置 | 计入审查轮？ |
|---|---|---|---|
| **A 材料不全** | 报告里出现"已实现/已完成"，但对应改动没有 commit，**或**没有原始命令输出 | **退回补齐**（只补材料，不重做） | **否**——补齐不是审查 |
| **B 机制未命中** | G-P0 某脚本没命中它自己的期望码；或既有 248 项回归 | 记为**缺陷**，带 fault_ref 交回 | **否**——这是 bug，不是争议 |
| **C 范围越界** | 改动了 P0 闭包外的符号/文件（E2/E3/F1′、S5、新机制、client） | 默认**回退**；若确有独立价值 ⇒ 登记为**候选**（带 fault_ref）留到后续批次，**不留在本批 diff 里** | 否；Owner 一句话可豁免 |
| **D 设计异议** | 说"契约/计划某条不对" | **必须带真实运行输出作反例**。带 ⇒ driver 按契约裁定；与冻结契约冲突 ⇒ 交 Owner/独立会话。不带 ⇒ 记为待办，本批按原文做 | **是**（唯一计数的类） |
| **E 卡住** | 报"无法机械判定" | driver 带证据裁定；**不得停在"等 driver 回话"**——先落 `docs/open-questions.md` + 说明本批其余项是否继续 | 否 |
| **F 全部命中** | G-P0 ①–⑨ 逐项命中期望码，且证据为外部/宿主采集 | driver 独立复跑（见 2.1）⇒ 记录 ⇒ 放行下一批 | **否**——检查不是轮次 |

**这张表的作用**：把上一轮"4 个门 + 1 个 Pro 轮、0 行实现"的形态**从结构上排除**。轮次只对争议收费。

### 3.2 已知的口径冲突（O-1…O-5）—— **driver 默认已定，Owner 一句话可改**

> **O-4 / O-5 是 2026-09-20 由 driver 裁定、**即刻生效**的两条。**计划文本的注记仍欠**（§11 ④ 与 §4.8 D2-b），由 writer 下次唤醒时补；**执行不因此暂停**，driver 也不自己改计划文本（免得又变成"既写计划又判计划"）。

- **O-4（依赖：**授权加 peer**）**：`@deepseek-ai/dsh-api-session-controller` **在宿主安装里存在**（`0.1.5-rc.2`，与现有 18 个 peer 的 `^0.1.5-rc.2` 对齐），本仓缺它（`require.resolve` = `MODULE_NOT_FOUND`，`node_modules/@deepseek-ai/` 无此项）。
  **安全依据（决定性）**：profile 的 `@deepseek-ai/` 下**只有 `cosmokit` 与 `schemastery`**，18 个 peer 一个都没进 profile ⇒ **peer 由宿主进程提供，不产生实体副本**；2026-08-16 那条双实例事故线是 `dependencies` 造成的，不是 peer。
  **落地约束（关键）**：**默认用 `ctx.get("sessionController")` + 调用点类型化错误，不写进 `inject`。** 理由：S2 原文只要求"缺席时类型化失败、不静默回退"，**没要求插件不加载**；而写进 `inject` = **硬依赖**语义 ⇒ 服务缺席时**整个 a2a 插件 waiting、`a2a_*` 全套工具消失**，失败面比调用点报错大一个数量级。只有能**实测**说明 `ctx.get` 达不到 S2 判据时才写 `inject`，并把理由写进 `fault_ref`。
  **验收（三件套之一即本次判据）**：加完依赖后 profile 的 `@deepseek-ai/` 下**除 `cosmokit`/`schemastery` 外出现任何新目录名 = 回归**；外加 `require.resolve` 从 lib 视角指向 host 路径 + health 200。
  **依赖边界（应记进 `docs/dsh-native-capabilities.md`）**：该包属 **API 层**（Web API 的会话控制器），插件 peer 依赖它 = 插件耦合到 API 层。上游若移动/改名 ⇒ S2 的落点随之失效。

- **O-5（判据：**D2-b / G-P0 ④ 改归属**）**：G-P0 判据 ④（`verify-d2-decision.mjs` 六用例）**全部是 E2/E3/P3-5 的内容** —— §4.8 的 D2-b 自己就写着「注意口径：这里的"路由"是**本插件的决策队列**（E2/E3）」，而 V1 明令 E2/E3/F1′ 退出 P0。这是**冻结文本的内部矛盾**（V1 收窄了 §3 / §10.5 / §11 的 ⑧，**漏改了 §11 的 ④ 与 §4.8 的 D2-b**）。裁定：
  (a) **D2 在 P0 的可交付部分 = D2-a + D2-c**（即时拒绝 / `asked`-`decided` 成对 / 回合有 `turn/end` / 留痕，**不依赖 E3**，"回合不悬挂"在此范围内闭合）；
  (b) **判据 ④ 不删除，改标「延后（landing = 批 2 / G-P2）」，编号不动**（不重编号，避免打断全部交叉引用）。依据是计划 §10.7 自己的标题：「延后项（**显式标注，不是漏掉**）」；
  (c) **D2-b 的六用例随 E2/E3 进批 2，并成为 G-P2 的判据项**，不是"以后有空再说"——它证的正是"决策队列不悬挂回合"，必须在 E2/E3 落地后再证一次；
  (d) **口径优先级（可复用规则）**：V 条目与**未同步更新的计划行**冲突时，**以 V 条目为准**；落败的那一行**标为延后 + 写明 landing**，**不许静默删除，也不许为了让它成立把已移出的范围再拉回来**（那是 fix-scope creep —— 前四轮唯一的反复失分机制）。
  于是本批 G-P0 的判定形态 = **①②③⑤⑥⑦⑧⑨ 各自命中期望码 + ④ 显式延后**；批 1 交付报告必须在「未做/未验证」栏写明这一条。


- **O-1｜G-S 与 G-P0 谁是本批出口。** 计划 §1 写"S 组必须**整体先做完**再开始 P0"；计划 §11.0 出口行写"P0 收窄版 = D1/D2/D3 + **真正依赖的 S 项** + D4"。二者只能取一个。
  **driver 默认取后者**（更晚写入、且写在裁定之后、且它是"收窄"的落点）：本批出口 = **G-P0**；G-S 只跑"`typecheck` 0 + `npm test` 全绿 + 既有 **248** 项不回归"这部分，**不要求 S1–S6 六个测试全绿**。此默认**必须在报告里显式标注**，不得默默改判据。

- **O-3｜在飞 `a2a.ts` 改动的去留。** 见 §4 的 F-A2A-2：这是真实缺陷修复，但 `src/a2a.ts` 正是 S1/S2 要重写的文件，**有被重写覆盖的风险**。driver 默认：**登记 fault_ref，并在 S2 的测试里加一条断言**（`readSessionText` / `listThreads` 的返回值必须过 `snapshotJsonValue` 往返），把它从"一次性修复"变成"回归项"。

## 4. 已核实的在飞事实（供后续任何会话直接引用，不必重查）

### F-A2A-1｜`a2a_send` 抛 `cannot get property "sandboxPolicy" without inject` —— 成因已定位

- `src/a2a.ts` 的插件 `inject` 声明为 `["agents", "sessions", "timer", "tools"]` —— **不含 `sandboxPolicy`**。
- 同一文件里 `sendRawA2A()`（其上方注释自述为 **`a2a_send` 与其跨 cwd 路径的共享入口**）以 `(ctx as any).sandboxPolicy?.resolve?.({ ... })` 访问它。`as any` 骗过类型层；`?.` 挡不住"未申报即抛"的 getter 本身。
- **锚点：commit `66cfc20` + 符号 `sendRawA2A` 与 `a2a.ts` 的 `inject` 导出**（行号会漂，不作为锚点）。
- **两种改法**（由 Implementer 按 fault_ref 决定）：①把 `sandboxPolicy` 加进 `inject`（**硬依赖**语义：整个 a2a 插件会等该服务出现）；②按 Cordis 规则改用 `ctx.get("sandboxPolicy")` 并处理 `undefined`（**可选依赖**语义，`receiptPolicy` 本就是可选参数）。`orchestra.ts` 已把 `sandboxPolicy` 声明为硬依赖，故本部署里两种都能跑通；差别在**插件在缺该服务时的行为**。

### F-A2A-2｜工具返回值里的字面 `undefined` 会让整个调用失败

- `readSessionText()` 与 `listThreads()` 的返回对象里出现过字面 `undefined` 的字段（`returned_turns`、`lastActivityMs`、`lastActivity`）。DSH 对每个工具结果跑 `snapshotJsonValue` 往返；字面 `undefined` 过不去 ⇒ 模型收到 `value is not lossless JSON` 而**不是数据**。
- 同文件既有的正确写法是 `...(x === undefined ? {} : { x })`（`title` / `role` / `createdAt` 就这么写）。
- **状态：已在飞**（Implementer 正在改，工作树未提交）。替代不了 §3.2 的 **O-3**。

## 5. 边的载荷格式（Implementer → driver，每次返回照此写）

```
结论           一句话，能判真假
证据           改动所在 commit + 可直接复跑的命令 + 原始输出（贴出，不转述）
                证据必须是外部/宿主采集的；角色自述只作材料
未做 / 未验证  如实列举。凡"已"字必须有 commit + 原始输出支撑，否则只能写"将/计划/未验证"
下一跳建议     你认为下一跳是什么（driver 定夺）
```

**缺"未做/未验证"一栏的返回 = A 类（材料不全），直接退回补齐**——这一栏是本项目前四轮唯一全程缺失、且代价最大的东西。
