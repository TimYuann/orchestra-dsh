## 1. 两条准入规则：采纳，并给你们看我们这边的落实

- **规则一（一条机制，一个已付过成本的故障）**：我们对**自己**也用它。v0.5.1 里那些"只写在提示词里、没有实例支撑"的机制，正是这条规则要拦的东西。落实：每个新机制在节点记录里带 `fault_ref`（指向一次现场实例/复核条目），指不出来的不做。
- **规则二（实现必须是大头）**：落实为节点记录的 `ratio{plan, implement, verify}`（**轮次为准**，token 可选、不要求精确），加一个定期 rollup；不设硬阈值，只在"长期超过"时产出告警，并要求**回头删机制**而不是继续加流程。
  （我们这边的实测支持这条：你们 29 小时那轮的分层消耗是"协调 44% / 实现 33%"，那正是机制过重的形状。）
- 两条推论接受：**能事后对账的不事前审批**；**能由机器推导的不许让角色填**（我们的胶囊 required 字段已按此压到最小）。
- 三条否定式约束接受：**不要求任何"开工前完备度"**。

## 2. E 组的落实（逐条 + 平台事实）

**E1 权限预分配、运行时不提权 —— 接受，而且这是 DSH 上最便宜的一条。**
机制：派发时钉死权限档与沙箱模式；审批策略钉成"永不询问" ⇒ 拒绝是**确定性的、当场返回的**，不是挂起。
⚠️ **措辞修正（必须改，否则是悬空承诺）**：我们能保证的是"**任何提权尝试都不会挂起回合，且留下类型化的拒绝记录**"，**不能**保证"模型不会尝试"——DSH 仍然会在工具结果里提示"可以申请提权"。建议 E1 的验收断言写成：
> 运行期任何提权请求都不得使回合悬挂；必须以确定性的拒绝收束，并留下可判定的事实（请求 id / 结果 / 原因码）。
（这正是你们 D2-a 的形状；差别只在于不假装模型不会试。）

**E2 三类请示各有去向 —— 接受。**
落实形态：**"决策队列"是一条记录，不是 UI、不是阻塞**。字段：`question / default / deadline / blocks:[nodeId] / state`。插件只强制一件事：**`blocks` 里的节点不得冻结或合并，其余一切继续跑**。——这样"只暂停依赖该答案的最小步骤"就变成**机械可判**的，而不是一句建议。

**E3 带默认值的请示 —— 接受，而且我们可以给出比"带超时"更强的保证：它根本不需要任何阻塞原语。**
机制：角色把「问题 + 我打算按 X 做 + 截止时间」写进节点记录 → 发一条**只带指针**的消息给 driver/oracle（C4）→ **然后继续干**。到点无人回答就按 X 继续，答案来了记为 override。
因为全程**没有"等待"这个动作**，**挂死风险为零**——不需要靠超时去兜。
"不可默认类 → 停在原地"的正确含义是：**记入 blocked 记录并结束回合**（不是等待），由看门狗唤醒 driver。这样 E3 的停止路径同样不会悬挂。

**E4 默认档 = "工作区修改" —— 已经是现状，零成本。**
插件的角色预设校验里，`danger-full-access` **从来不是合法默认**（角色只允许只读 / 工作区修改两种）。这条只需保持。

## 3. 三处整合补丁（不写会漏）

**3.1 A1 × E3：override 来得太晚怎么办。**
若 override 在候选**冻结之后**才到 ⇒ 候选 generation +1、旧证据与旧审查全部失效（A1 已有语义）；若**已合并**才到 ⇒ 只能走 A4"合并后终态"：精确 revert 或新建修复节点，**不得回改历史**。
不写这条，"带默认值继续"会悄悄退化成"自己拍板就算了"——正好是故障 1（旧结论被挪到新代码上）的另一种形态。

**3.2 worktree 的豁免集。**
worktree 落在项目内 ⇒ 它本身会成为主工作区里的未跟踪内容；`orchestra/` 状态目录、工具缓存同理。所以收工对账在判"声明写入面"时必须带**豁免集**（`.worktrees/`、`orchestra/`、以及明示的工具缓存路径），否则每天都会被自己的脚手架点名。同时 `.git/info/exclude` 要写入这些路径。

**3.3 E2 的"产品/权限/风险"不进问询 ⇒ 必须有一个可见出口**，否则等于静默丢弃。
落实：决策队列按时长分级；长龄项进入定期报告；**发布资格类只能由人关闭**，不允许被默认值消化。

## 4. 两处诚实边界（请写进文档，别当现状）

**4.1 "运行期不接受提权" ≠ "模型不会尝试"**（见 §2 E1 的措辞修正）。

**4.2 "禁止真实外部调用"无法强制 —— 这条建议改写需求措辞。**
DSH 的沙箱是**纯文件效果**策略，官方原文：
> `read-only` permits only required sinks… `workspace-full` … `danger-full-access` bypasses confinement. **Network and process visibility are outside this vocabulary.**

即：**没有网络平面，也没有开关**；而你们裁定 2.3 又明确"不做沙箱实现"。所以我们能做到的是：
> **必须声明 + 执行时按声明采集 + 不一致即判不合格（`unqualified`）。**

可以由执行层把代理变量指向本地垃圾桶并计数，作为"尽力而为的封堵 + 可判定的证据"——但**不声称是强制**。
**好消息**：你们真正付过成本的那个故障是"**被静默拦截了几个小时，表现只是连接错误 / usage=0**"——那是**可见性**问题，不是许可问题。"声明 + 采进证据 + 不一致判不合格"正好治它，而且能 100% 做到。
建议需求文档把"必须显式声明，并在执行时强制"改为"**必须显式声明，并在执行时按声明判定；不一致即不合格**"。
