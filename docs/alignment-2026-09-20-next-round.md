## 3. 本轮复核确认的事实（改动依据，证据见关联文件）

1. **发布阻断项**：懒加载与重激活创建的角色会话，在进程重启后**失去角色组合**（只剩宿主全局工具，读不了文件、改不了代码），不报错、无检测。已定位两处成因：预设不在 DSH 名册里 + 恢复路径不带挂载动作。DSH 对"发布了一个没有加入预设的 agent"有官方告警，实测状态与其描述一致。
2. **审批永久挂起**：DSH 审批链**没有超时**；界面受理后等人点击 = 永久挂起。已在 E2E 会话日志中实证（一个只读角色 asked 无 decided），并确认整轮 E2E **没有任何角色被钉成"永不询问"**。
3. **向用户提问同样没有超时**，但**角色手里没有该工具**（实测角色工具清单），所以"角色问用户"目前是构造性不成立的——只要永不把该工具行加进角色预设。
4. **停摆兜底**应改为订阅"回合关闭前被 await 的那个事件"，在该时刻要求角色补交报告；"卡在审批"可由"asked 无 decided"观测。
5. **投递、唤醒、冷恢复 DSH 原生具备**；插件唯一不可让渡的是"消息生命周期（认领/回答）"与编排语义本身。

## 7. UCBIP 侧裁定摘要（2026-09-20 已回）

原文：`reports/conflicts-round1-answer-from-ucbip.md`（255 行，引用请以原文为准）。执行计划见 `docs/plan-0.8.0-delivery-layer.md`。

### 7.1 三条前置裁定

1. **git 边界**：插件**不实现 git**（不实现对象模型、不遍历文件算树、不维护 refs），只调外部 git plumbing 并采信 git 自己的输出；**不许采信角色自报的 SHA**。
2. **信任模型**：不要求对抗"绕过插件直接改文件系统/仓库/进程表"的参与者；因此**不要求原子性**，只要求两条——**记录不可改写** + **账实不符可检测**。
3. **证据哲学**：判定所依赖的字段**必须由宿主采集**；解释性字段可角色自述；一切降级**优先降覆盖率，不降可判定性**。

### 7.2 冲突结论（逐条）

1. **合并后失败不可回卷**：不承诺原子性；由"记录不可改写"保证终态，由"每次判定重新读 git 与记录比对、不一致报类型化账实不符"发现人工介入。
2. **树比对**：只用 git —— 预演 `git merge-tree --write-tree`，合并后 `git rev-parse HEAD^{tree}`，比两个 tree id；**禁止自己遍历文件**（否则等于重写 git 的二进制/符号链接/行尾/忽略规则）。
3. **worktree**：由**插件**用外部 `git worktree` 创建与回收；路径确定性（`node id → 路径`）；可重入；dirty 不自动删。
4. **单一写者 = 租约**：锚不是分支、不是目录、不是 worktree 名；写面必须**可枚举**（路径前缀重叠即排队，不可枚举则退化为仓库级独占）；**不要用 `index.lock`** 当写者判定。
5. **验收执行**：插件自建**极薄执行层**；结构化记录**必需**，"经由一个会话可回放"**可选且不得成为实现前提**；不做沙箱实现（用 DSH 已有的）、不做 CI 集成。
6. **角色与插件边界**：角色 = 执行者 + 报告者（不能定义"什么算完成"、不能给自己发通过）；插件 = 编排者 + 判定者 + 记账者；**候选身份归插件**——"身份是事实，事实不能由被判定方持有"。
7. **团队上移到仓库级**：一个仓库一个团队，`orchestra/` 只写主 worktree，节点工作区是 `.worktrees/<node-id>`，状态不进工作区；对现有部署**兼容**（主 worktree 即当前工作目录）。理由：按 worktree 建队会破坏 controller 唯一性；状态散落会产生第二份花名册。
8. **验收脚本**：节点作者提供，首选仓库既有入口，形态为"仓库相对路径 + 参数 + 期望"；脚本内容一变 ⇒ 候选 generation +1、旧审查与旧证据失效（不必改代码 commit）；结果三值 `pass | fail | unqualified`。
9. **基线**：插件采一次、存插件状态区（**不进 git**）；对比必须做名字 + 位置/类型的差集并要求解释；基线 SHA 偏离或基线外文件被改 ⇒ `stale_baseline`，**不许用过期基线判"无新增红"**。
10. **胶囊分两层**：编排事实（现有 `orchestra/` 那套，插件写）与**工作现场事实**（新层：角色写关键字段、插件校验完整性）；机器可推导字段由插件生成，冲突以插件为准；角色字段缺失 ⇒ 标记 `incomplete`、允许续做、续做时补齐，**不得阻塞**。
11. **新增"节点记录"层**：插件持有与写入；不进 git；但**必须能被非插件读者读懂**（schema 版本 + 纯 JSON/YAML），读取路径三条（插件工具查询 / 确定性路径推导 / 按需导出）。
12. **D2 写成三条验收断言**：钉死的路径不得挂起回合；走路由必须带截止时间、到点默认拒绝并继续；回合结束必须留下可判定事实（请求 id / 结果 / 原因码）。**N7 明确不降级。**
