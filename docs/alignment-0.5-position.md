# 0.5 定位：强度分级（对齐稿）

> **用途**：这是 orchestra-dsh 开发线对"要机制到什么程度"的立场声明，供与 UCBIP / workflow-optimizer 侧来回对齐。
> **状态**：谈判稿，不是规格。措辞与分档都可改；改的目的是对齐，不是冻结。
> **2026-09-20 round-3 后更新**：已并入 **E 组（权限与请示）**、**D2 的分型修订**、以及 **A1×E3 的接口**；对方已确认**不做**开工前完备度闸 / 词汇闸 / 整批拒的原子收工。我方答复见 `docs/alignment-round2-from-orchestra.md`。
> **一句话**：我们做 0.5 —— **对"事实与账目"用机制，对"意图与路径"用判断。**

---

## 1. 三个位置

| 档 | 是什么 | 代价 |
|---|---|---|
| **0** | 记录、路由、顺序**全靠角色自觉**（提示词纪律 + 人工盯） | 漂移与幻觉无人兜底（实测：规则书出现 73 次、执行 0 次） |
| **1** | **纯机械执行流**：开工前必须把"怎么验证"写全，等于要求这次开发本身是确定的 | 探索被排除——不能造新词、新函数，落点未知的活干脆不能开工 |
| **0.5（目标）** | **事实与账目机械化；意图与路径保留判断** | 需要我们逐条划清界线，而不是整体收紧或放松 |

## 2. 我们要防的是"漂移"，不是"想法变了"

机制只针对三种漂移，**不针对探索本身**：

1. **事实漂移**：谁、什么时候、改了什么、结果是什么，事后说不清或可被改写；
2. **判据漂移**：看到结果之后才改"什么算做完"（移动球门、事后合理化）；
3. **传递漂移**：正确性依赖"消息送达"，事实住在对话或消息里，链路一断就重建不出。

"这次做出来发现方向要调整"不属于漂移——那是探索，**必须允许**。

---

## 3. 判定一条规则放哪一档：三条判据

1. **它拦的是"动作"还是"说法"？** 拦动作（且这个动作由插件拥有：准入、记账、验收执行、git 操作、合并）→ 可以硬拦；拦"说法"→ 只能记录 + 对账点名。
   （DSH 里会话是长驻的、模型自主决定下一步，**没有 hook 位置**能拦住任意文件写入。这是平台事实，不是取舍。）
2. **它要求"提前知道"吗？** 要求开工前就知道全部答案 → 那是 1 档，不做；只要求"在某个时点冻结、之后改动即失效" → 0.5 档，做。
3. **复核是宿主能重算的吗？** 能（跑命令、读 git、对账）→ 做，便宜；要再跑一轮 LLM 会话才能判 → 弱化，别把成本乘上去。

## 4. 强度分档（对着需求文档的能力编号）

| 能力 | 0.5 的形态 | 档 |
|---|---|---|
| **A1 候选身份** | **强，但改冻结时点**：验收清单不必"开工前写完"，但必须**在门运行前写完并冻结**；冻结后再改 ⇒ 候选 generation +1、旧证据与旧审查结论失效 | 强（改形） |
| **A2 系统执行验收** | 宿主采集全部判定字段（命令/cwd/关键环境变量/退出码/输出与产物 hash/时间/外部调用模式）；角色只能写解释性字段。**不做环境建模** | 强 |
| **A3 合并门 + CAS** | 归并前重读现行状态、要求纯追加、真分叉即拒；树比对只用 git | 强 |
| **A4 合并后不可回卷** | "已合并但验证失败"是终态，记录不可改写；账实不符靠重新读 git 发现 | 强 |
| **A5 写面隔离** | **准入硬拦**（写面重叠的节点不得同时开工/冻结）+ **门上对账点名**（申报范围外的改动）；**不拦**会话对文件的任意写入 | 弱（落点改变） |
| **A6 证据复用** | 同候选树 + 同命令 + 等价条件即可引用既有读数 | 强 |
| **A7 失败对比粒度** | 必须给出失败的名字 + 位置/类型，不接受只看名字；给不出可解析输出 → `unqualified` | 强 |
| **B1 缺陷登记** | 机器可读、只存活跃项、设上限、超限先清理 | 强 |
| **B2 强制摄入** | 相关缺陷必须逐条表态，**允许一句话理由**（不要求论证）；"相关"的判定必须可复核 | 弱 |
| **B3 所有权与事务声明** | **拆两件事**：① 同一写面出现第二个活跃写者且无裁定 → **硬拒**（靠租约机械可检，即 N5）；② "canonical owner 未定"这类**声明完备性**要求 → 只登记、不阻断开工（close 时作为 residual 出现），交 driver 裁定 | 强（①）+ 弱（②） |
| **C1 胶囊** | 骨架字段机械生成；**required 只留机器推不出来的那几项**（下一步、已知失败、不可重复的外部动作）；缺失标 `incomplete`，**不阻塞** | 强 + 弱 |
| **C2 独立续做** | 只读"胶囊 + 节点记录 + git"即可继续 | 强 |
| **C3 上下文可观察** | 纯观测，不设配额、不强制轮换 | 弱 |
| **C4 消息不承载事实** | 消息只带指针与唤醒；任何正确性条件不得依赖消息送达 | 强 |
| **D1–D4** | 照原样（三处现场缺陷 + 工具闭包守卫）——这些是既有承诺，不因 0.5 放松 | 强 |
| **E1 权限预分配** | 派发期钉死档位与沙箱；运行期**不接受提权**——被拒即记录 + 上报，由编排者改派或调配置重派 | 强 |
| **E2 三类请示各有去向** | 技术分叉 → oracle；范围/依赖/资源 → driver；产品/权限/风险 → **决策队列**（只暂停依赖该答案的最小步骤）；安全/凭据/不可逆 → 停止相关动作并通告 | 强 |
| **E3 带默认值的请示** | 任何请示自带"若不回答我就按 X 做" + 截止时间；到点**用申报默认值继续**并留痕可覆盖。**例外（不默认、停在原地）**：权限变更、数据处置、不可逆外部动作、发布资格 | 强 |
| **E4 默认档 = 工作区修改** | "完全权限"只能声明 + 批准，不得作默认（**已是现状**：角色预设校验里 `danger-full-access` 从不合法） | 强（零成本） |
| **F1′ 设计门独立审查** | **设计门必须由独立会话（fresh context、非设计者本人）作出**；记录设计者与审查者的 session id 与 model id；**存在第二个可用模型时优先用**（满足记 `satisfied`，不存在记 `degraded`、不阻塞）；普通实现审查不强制 | 强（零成本） |

**脚本化的边界（一句话）**：**脚本管验收与对账，不管设计与实现。**
验收脚本、范围对账、git 状态核对、基线采集——全部脚本化、宿主执行、机械判定；任务怎么拆、角色怎么配、要不要加一轮评审、用什么方案——**由 driver 判断，不进脚本**。

### 4.1 能力边界（**不得声称**的事）

> **canonical 清单已独立成文：`docs/capability-boundaries.md`（双方共用，7 条）。** 以下不再复述，避免表述漂移。

1. **运行前提声明与实际一致（不是"禁止外呼"）**：DSH 沙箱是纯文件效果策略（原文 *Network and process visibility are outside this vocabulary.*），**不可强制**。严厉度**不对称**——见下表；无法观测时标 `unverified`，**不得把"未验证"写成"已验证"**；尽力封堵标 `best-effort`，不得当强制证明。

   | 声明 | 实际 | 判定 |
   |---|---|---|
   | 需要真实外部调用 | 已发生 | ✅ 合格 |
   | 需要真实外部调用 | **未发生** | ❌ **不合格**（致命方向：假绿） |
   | 不需要 | 未发生 | ✅ 合格 |
   | 不需要 | **已发生** | ⚠️ 告警 + 记录，默认不阻塞 |

   "不需要却发生"判不合格**仅三种情形**：① 该断言本身就在测"不外呼"；② 该调用有外部副作用（邮件/推送/部署/扣费）；③ 该场景明确依赖"可离线运行"（CI、无网、需确定性复现）。
   **一般化**：任何**运行前提**（树身份、环境、模式、外呼有无）都必须**声明 + 采集 + 一致**，才配叫证据——这条同时覆盖 pytest rootdir/PYTHONPATH 陷阱与 N3。
2. **不能拦任意文件写入**：没有 hook 位置。只能"准入硬拦 + 收工对账点名"。
3. **"宿主采集"只保证**：判定字段**不是角色自报的**、且**与声明一致**；**不保证**被测程序内部没做别的事。
4. **"合并门通过"不保证代码是对的**：只保证审查、证据、写面范围、候选身份都绑定在这次候选上。
5. **"证据复用"不保证读数适用于新语境**：只保证判定所依赖的条件（树、命令、环境）逐项可比。
6. **"运行期不接受提权"只保证不悬挂 + 确定性拒绝 + 留痕**，**不保证模型不会尝试**（DSH 仍会在工具结果里提示"可以申请提权"）。
7. **换会话 ≠ 换模型**：独立会话买到的是"没有作者的上下文污染"，**买不到**"不同的先验"。不得把独立会话审查说成等价于异质模型审查。

## 5. 明确不做（属于 1 档，且会伤害探索或制造活锁）

1. **不做"开工前必须写完验收标准"的完备度闸**：那要求这次开发是确定的，落点未知的活就没法开工。→ 改为"**门运行前冻结**"。
2. **不做"不许造新词/新函数"的词汇闸**（登记册式许可制）：→ 改为"**登记而非许可**"——新概念出现时记进登记册、链上留痕，下一次会话可查，但**不阻断本次**。
3. **不做"整批拒零动作 + 工地卫生"的原子收工**：它假设"重跑很便宜"，而我们的重跑是重建上下文、重派会话，贵一个量级；而"工作区有草稿/临时文件/子代理残留"是 LLM 会话的常态 → 会高频活锁且没有自动出口。→ 改为：**门只判该节点声明过的写入面**，范围外降级为告警 + 点名。
4. **顺带不做**：进程取证式身份（DSH 里一个 Host 一个 pid，且重启即全拦）；全局"同一问题问五遍看一致"（会把我们已经很贵的会话成本再乘五，只在低频高影响的判断上可选）。

## 6. 两条准入规则（对方 round-3 提出，我方采纳）

1. **一条机制，一个已付过成本的故障**：指不出故障、或理由只是"听起来更稳/更规范" ⇒ 不做。落实：每个机制在节点记录里带 `fault_ref`。
2. **实现必须是大头**：节点记录带 `ratio{plan, implement, verify}`（轮次为准，token 可选）；**长期超过实现 ⇒ 视为机制过重，回头删机制**。

推论：**能事后对账的，不做事前审批**；**能由机器推导的，不许让角色填**。

## 7. 我们这一侧不因 0.5 放松的东西

- **D1** 角色身份持久：每个角色都带着完整身份出生，三种创建路径一视同仁，重启后可核；
- **D2** 无人值守不得悬挂，**按分型收场**（round-3 修订）：**可默认类**到点用申报的默认值继续、留痕可被覆盖；**不可默认类**（权限变更 / 数据处置 / 不可逆外部动作 / 发布资格）停在原地——但"停"的含义是**记入 blocked 并结束回合**，不是等待。无论哪一型，**回合必须收束并留下可判定事实**。
- **D3** 归档先停后记；
- **D4** 工具闭包守卫；
- **证据哲学（UCBIP 裁定 3）**：判定字段只由宿主采集，角色自述只作材料——这条是 0.5 的地基，不是妥协项。

## 8. 与 E 组的三个接口（不写会从缝里漏）

1. **A1 × E3：override 来得太晚。** override 在候选**冻结之后**到 ⇒ 候选 generation +1、旧证据与旧审查失效；**已合并**才到 ⇒ 只能走 A4"合并后终态"（精确 revert 或新建修复节点），**不得回改历史**。否则"带默认值继续"会退化成"自己拍板就算了"。
2. **E2 的机械形态。** "决策队列"是一条**记录**（`question / default / deadline / blocks:[nodeId] / state`），不是 UI、不是阻塞；插件只强制"`blocks` 里的节点不得冻结或合并"，其余继续跑——"只暂停最小步骤"由此变成机械可判。
3. **worktree 的豁免集。** worktree 在项目内 ⇒ 它本身是主工作区的未跟踪内容；收工对账的"声明写入面"判定必须带豁免集（`.worktrees/`、`orchestra/`、明示的工具缓存），并写入 `.git/info/exclude`。

---

## 9. 两处诚实边界（写进文档，别当现状）

1. **"运行期不接受提权" ≠ "模型不会尝试"**：DSH 仍会在工具结果里提示"可以申请提权"。我们能保证的是**不悬挂 + 确定性拒绝 + 类型化留痕**。
2. **"禁止真实外部调用"无法强制**：DSH 沙箱是**纯文件效果**策略，官方原文 *"Network and process visibility are outside this vocabulary."* ——没有网络平面也没有开关。只能做到 **声明 + 按声明采集 + 不一致即 `unqualified`**（可用代理变量指向本地垃圾桶做"尽力而为的封堵 + 可判定证据"），**不声称是强制**。对方真正付过成本的故障是"被静默拦截数小时、只看到连接错误"，那是**可见性**问题，此方案正对其症。
